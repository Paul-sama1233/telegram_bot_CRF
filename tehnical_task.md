Техническое задание: Телеграм-бот для публикации контента (Kivy + SQLite)
1. Общее описание проекта
Приложение для управления публикациями в Telegram-каналах/группах через бота с возможностью планирования, шаблонизации и отслеживания статуса отправки.

2. Технологический стек
GUI Framework: Kivy (уже есть готовый UI)

База данных: SQLite

Telegram API: python-telegram-bot или aiogram

Планировщик задач: APScheduler или Celery для отложенных публикаций

Медиа обработка: Pillow для изображений

5. Структура базы данных
sql
-- Таблица ботов
CREATE TABLE bots (
    id INTEGER PRIMARY KEY,
    token TEXT UNIQUE,
    bot_name TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица публикаций
CREATE TABLE posts (
    id INTEGER PRIMARY KEY,
    bot_id INTEGER,
    channel_id TEXT,
    message_text TEXT,
    media_paths TEXT, -- JSON список путей к файлам
    status TEXT, -- 'draft', 'scheduled', 'sent', 'error'
    scheduled_time DATETIME,
    sent_time DATETIME,
    message_id INTEGER, -- ID сообщения в Telegram
    error_message TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (bot_id) REFERENCES bots(id)
);

-- Таблица шаблонов
CREATE TABLE templates (
    id INTEGER PRIMARY KEY,
    name TEXT,
    content TEXT,
    media_paths TEXT,
    variables TEXT, -- JSON список переменных
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Таблица inline-кнопок
CREATE TABLE inline_buttons (
    id INTEGER PRIMARY KEY,
    bot_id INTEGER,
    text TEXT,
    url TEXT,
    template_id INTEGER,
    row INTEGER,
    FOREIGN KEY (bot_id) REFERENCES bots(id),
    FOREIGN KEY (template_id) REFERENCES templates(id)
);
6. Требования к логике
6.1 Отправка сообщений
Поддержка массовой отправки в несколько каналов

Очередь отправки с ограничением 30 сообщений/сек (лимит Telegram)

Возможность добавления inline-кнопок к сообщениям

6.2 Обработка медиа
Поддержка форматов: JPG, PNG, GIF, MP4, PDF

Сжатие изображений при необходимости

Локальное кэширование медиафайлов

6.3 Безопасность
Шифрование токенов в БД

Валидация входных данных

Защита от SQL-инъекций

7. График разработки (оценочно)
Этапы 1-3: 10-14 дней (базовая функциональность)

Этапы 4-5: 4-6 дней (расширенные функции)

Этап 6: 2-3 дня (тестирование)

Итого: 16-23 дня

8. Дополнительные рекомендации
Для Kivy: Использовать ScreenManager для навигации между экранами

Для SQLite: Добавить индексы на часто запрашиваемые поля

Логирование: Реализовать детальное логирование всех операций

Конфигурация: Вынести настройки в config.ini файл

Обработка ошибок: Пользовательские сообщения об ошибках на UI
